## B. Phase 0 合格ゲート
- [ ] G01: 確定仕様と未確定事項の区分がレビュー・承認され、docs内の矛盾が解消
- [ ] G02: 対象の各計算に使用する式・前提・単位・適用範囲を明文化
- [ ] G03: 法令・規程・メーカー値の原典、版、表、利用可否、検証日を記録
- [ ] G04: 単相/三相、境界値、欠損値、異常値を含む手計算照合ケースを整備
- [ ] G05: 布設方式、温度、集合条数、始動・保護条件などの未確定事項に判定ルールを付与
- [ ] G06: Android/iOS/PC、オフライン、保存・復元、帳票、キーボード非遮蔽の試験手順を用意
- [ ] G07: 未検証条件では「適合」を表示せず、「要確認」または「未判定」にする試験を定義
- [ ] G08: 上記の証拠リンクと判定責任者の承認を記録

## C. 判定方法
- **PASS**: G01～G08が全て満たされ、証拠が確認可能。
- **CONDITIONAL**: 未解決項目の対象機能を明示して開発対象から除外する場合のみ、対象を限定した試作を許可。安全性に関係する未検証値での選定は不可。
- **FAIL**: 根拠不明の計算式・数表、誤った適合表示、再現できない試験がある。

## D. 変更管理
1. 本書をレビューし、採否を決める。
2. 承認された項目のみ別PRで仕様書に反映。
3. Phase 0のゲートを通過するまでは本格実装を開始しない。
4. 計算結果の改訂履歴・差分比較は将来フェーズに維持する。
